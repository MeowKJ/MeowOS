# Meow OS 产品目标与 UI 设计

版本：0.1.0 设计基线
目标硬件：Radxa Cubie A5E + WX101CH021I-40Z 触摸屏 + A5E 扩展背板

## 1. 产品定位

Meow OS 不是通用 Linux 桌面，也不是 Android 仿制品。它是运行在固定硬件上的轻量设备系统壳：开机即可触摸操作，普通功能不暴露终端、窗口管理器和 Linux 配置细节。

第一阶段只解决四件事：

1. 稳定显示、正确触摸、始终能返回。
2. 把网络、电池、音频、隔空喵传和存储状态集中管理。
3. 提供可重复验证硬件的基础应用。
4. 形成可刷写、可恢复、可继续扩展的镜像和仓库。

## 2. 硬件基线

| 模块 | 实际器件/接口 | Meow OS 职责 |
|---|---|---|
| 主机 | Radxa Cubie A5E | Linux、Qt Quick、系统服务 |
| 显示 | WX101CH021I-40Z / JD9366TC / 800×1280 | 以 1280×800 原生横屏布局输出，最终逆时针 90° 映射到物理屏 |
| 触摸 | Jadard TDDI / I²C | 与显示共用同一旋转矩阵，支持单指、拖动和多点触控 |
| 充电与路径 | SGM41511YTQF24G/TR | NVDC 路径、充电状态、输入状态、故障和充电策略 |
| 电量计 | BQ27220YZFR | SOC、电压、电流、温度、容量、健康度和预计时间 |
| MCU | CH592F | USB/BLE 外设和常驻 USB IAP 升级 |
| 音频 | NS4168 / I²S | 内置扬声器、音量、静音和测试音 |

网表 `Netlist_Schematic1_2026-08-21.tel` 中，SGM41511 与 BQ27220 共用 A5E 的 `SDA/SCL`，并分别使用 `BAT_INT`、`BQ_INT`。BQ27220 的连接为：

- `C1/SRP → _BAT+`，即电池 PACK+ 一侧；
- `C2/SRN → BAT+`，即系统/充电器一侧；
- `C3/BAT → _BAT+`，即 PACK+ Kelvin 电压采样；
- `R16=10 mΩ` 位于 `_BAT+` 与 `BAT+` 之间。

这与 TI 给出的 system-side high-side sensing 方向一致，当前网表不是 SRP/SRN 短接。PCB 仍必须保证 SRP、SRN 和 BAT 是从电阻焊盘/电池端独立引出的 Kelvin 走线。

## 3. 设计原则

### 3.1 设备优先

- 冷启动后直接进入 Meow OS，不显示桌面和终端光标。
- 所有常用操作可只靠触摸完成。
- 网络断开、没有电池数据、CH592F 未连接时仍可进入系统设置和诊断页。

### 3.2 数据诚实

- 数值必须来自 Linux 驱动、`power_supply`、ALSA 或 Meow 硬件服务。
- 未接入驱动时显示“未检测到”或“驱动未就绪”，不显示 0%、0 V 等误导值。
- SGM41511 负责充电/路径状态，BQ27220 负责电量测量；UI 不混淆两颗芯片的职责。

### 3.3 可恢复

- Meow OS 应用崩溃由 systemd 自动拉起。
- 设置变更可回退，显示配置保留安全 profile。
- CH592F 首次通过 SWD 或 ROM Boot 写入常驻 IAP；以后正常升级只需 USB，不按 BOOT。
- CH592F 应用损坏或 IAP 区损坏仍保留物理 BOOT/SWD 恢复路径。由于 `CH592_RST` 没接 A5E，不能承诺任何损坏状态都能由 A5E 无人值守恢复。

### 3.4 可扩展

- UI 不直接访问 `/dev/i2c-*`、GPIO 和 sysfs；统一通过后端接口读取。
- 显示采用 profile：逻辑分辨率、物理分辨率、旋转、触摸矩阵和 QPA 后端均可替换。
- 应用以页面组件接入，不依赖固定屏幕物理方向。

## 4. 信息架构

```text
静态启动画面
└── 首页
    ├── 点击测试
    └── 设置
        ├── Wi-Fi
        ├── 电池
        ├── 声音
        ├── 隔空喵传
        ├── 显示与触摸
        ├── 存储空间
        └── 关于本机
```

首页只放高频入口和真实状态，不做应用抽屉。设置采用 iPadOS 式双栏结构：左侧分类，右侧内容；不是复刻 iOS 图标和状态栏，而是沿用其清晰的分组、层级和触控尺寸。

## 5. 返回规则

所有二级页必须同时提供三种返回方式：

1. 设置页把圆形返回按钮和“设置”合并在左侧栏顶部；普通应用页使用悬浮圆形返回按钮与紧凑标题，不再绘制横跨全屏的标题栏。
2. 从屏幕左边缘向右滑返回。
3. 键盘 `Esc` 返回，便于开发调试。

首页忽略返回动作，不退出系统壳。设置右侧分类切换不入页面栈；从设置返回时只返回首页，避免连续多次返回。

返回组件本身不占用独立的全宽布局行。最小触控区保持 52×52 px，视觉按钮可缩小到 40–48 px；应用内容从状态栏下方直接开始。

## 6. 页面设计

### 6.1 启动画面

- 背景为暖白到浅粉的柔和渐变。
- GitHub 头像以圆形静态显示，底部显示 `Meow OS 0.1.0`。
- 不使用缩放、旋转、淡入或页面滑动效果；启动画面短暂停留后直接进入首页。

### 6.2 首页

- 顶部 56 px 状态区使用 Lucide SVG：Wi-Fi 图标、扬声器图标与音量百分比、加长的 iOS 式电池图标。电池内部使用较大字号显示百分比，充电时填充变绿；数值更新不使用过渡动画。
- 主页不显示用户头像、用户名、问候语、“应用”标题、IP、网络名、芯片连接和“设备状态”入口；这些内容对固定设备的主要操作没有帮助。
- 页面中央只放应用图标和名称，取消应用外层大卡片。应用区采用数据模型驱动的自适应网格；0.1.0 仅注册“点击测试”和“设置”，增加应用时只新增应用描述，不修改首页布局。
- `Meow OS 0.1.0` 固定放在主页最下方居中，只出现一次。
- 删除底部电池、CH592F、扬声器三张重复硬件卡。顶部状态栏是纯显示层，完全不接收点击和触摸，避免误触；Wi-Fi、声音、电池设置只从“设置”应用进入，CH592F 也只保留在设置中。

### 6.3 点击测试

- 测试区覆盖除导航栏外的全部可触区域。
- 每个触点使用不同颜色、编号和坐标；同时显示当前触点数与历史最大触点数。
- 提供“清除轨迹”和“重新校准”两个明确动作。
- 坐标显示使用逻辑横屏坐标 `0…1279 × 0…799`，方便判断旋转、镜像和偏移。
- 返回按钮始终位于测试区之上，不能被多点触控层吞掉。

### 6.4 电池

电池页顶部只展示用户最需要的信息：电量百分比、充电/放电状态和剩余时间。下面分为两组。

`BQ27220 电量`：

- SOC、SOH；
- 电池电压、平均电流、温度；
- 剩余容量、满充容量、设计容量；
- 预计可用时间或预计充满时间；
- 循环次数和电量计初始化状态。

`SGM41511 充电与电源路径`：

- VBUS 是否有效、输入类型；
- 未充电/预充/快充/充满；
- NVDC 最低系统电压调节、VINDPM、IINDPM、热调节状态；
- NTC、输入、电池、升压、看门狗和安全计时器故障；
- 当前配置的输入限流、充电电流和充电截止电压。

普通模式只读。改变充电电流、截止电压、OTG 和 ship mode 等危险操作只能放入受保护的“开发者选项”，并要求二次确认。

### 6.5 隔空喵传

- 显示 USB 连接、运行固件版本、IAP 版本、设备标识和应用区校验状态。
- “选择固件”只接受带 Meow 固件头、目标芯片、长度和校验值正确的文件。
- 升级流程：让运行应用进入 IAP → 等待重新枚举 → 擦写应用区 → 校验 → 启动新应用 → 回读版本。
- 更新中禁止退出，界面同时给出百分比、当前阶段和可执行的失败恢复说明。
- 正常更新无需按 BOOT；物理 BOOT/SWD 只作为首次烧录和救砖入口。

### 6.6 声音

- 输出设备固定显示为“内置扬声器 · NS4168”。
- 提供主音量和短促猫咪提示音测试；若硬件为单声道，界面只显示单声道，不伪造声道选择。
- 音量由 ALSA 软件音量或管线增益控制；NS4168 本身没有独立 I²C 设置页。
- 没有注册 I²S 声卡时显示“音频驱动未就绪”和设备树诊断入口。

### 6.7 显示与触摸

- 显示当前 profile、逻辑/物理分辨率、刷新率和旋转方向。
- 正式界面固定采用逻辑 1280×800；物理 800×1280 逆时针 90° 输出。
- 提供触摸诊断和校准，不把整个旧竖屏 UI 简单旋转拉伸。

## 7. 视觉规范

- 主背景：暖灰 `#F4F3F7`；卡片：`#FFFFFF`；主要文字：`#24212B`。
- 品牌色：猫爪粉 `#FF7FA7`；功能紫 `#786AEF`；正常绿 `#43B58B`；警告橙 `#F2A33B`。
- 圆角：大卡片 28 px，设置分组 20 px，按钮 14–18 px。
- 最小触控区域 52×52 px；页面边距 32–40 px；设置侧栏约 320 px。
- 中文字体使用 Noto Sans CJK SC；标题 32–40 px，正文 18–22 px，辅助文字不小于 15 px。
- 阴影只用于悬浮层和弹窗；普通设置分组用浅色层次和分隔线，不堆叠重阴影。
- 页面切换、启动画面和状态更新均不使用动画，优先保证触摸响应和稳定帧时间。
- 图标统一使用可本地打包的 Lucide SVG（ISC），不使用 Emoji、字符图标或临时手绘 CSS 图形。

## 8. 后端边界

```text
QML 页面
  ↓ 只使用稳定属性和命令
SystemBackend / Meow Hardware Service
  ├── NetworkManager
  ├── Linux power_supply
  │   ├── SGM41511 charger driver
  │   └── BQ27220 fuel-gauge driver
  ├── ALSA / ASoC / NS4168 simple-audio-card
  ├── CH592F USB updater
  └── display profile + evdev/libinput
```

QML 不解析寄存器。芯片驱动负责单位、符号、有效性、缓存、错误和中断；UI 只接收结构化状态。

首页应用不直接写成两个固定 QML 卡片，而由 `AppRegistry` 提供模型。每个应用至少声明：

```text
id · title · icon · component · order · visible
```

首页 `GridView` 只负责根据模型排列和启动应用。后续增加应用时注册一条描述即可；隐藏、排序或移除应用也不需要修改首页布局。系统状态图标由独立 `StatusModel` 提供 `wifiState`、`volumePercent`、`batteryPercent` 和 `charging`，与应用注册表分离。

## 9. 0.1.0 验收标准

- 开机不出现终端光标，启动动画结束后进入原生横屏首页。
- 触点位置与画面一致，四角误差可接受且无 90°/镜像错误。
- 所有二级页均可通过按钮、左边缘手势和 `Esc` 返回。
- Wi-Fi 可扫描、连接、忘记并在重启后自动连接。
- 两颗电池芯片缺失或故障时，页面显示明确错误；正常时显示真实参数。
- 插拔电源后，充电状态和系统电源状态能自动刷新。
- I²S 声卡能完成测试音播放，音量与静音生效。
- CH592F 完成一次不按 BOOT 的 USB 升级，并在升级后回读新版本；失败不会覆盖常驻 IAP。
- 镜像可从官方基础镜像构建，生成压缩包与 SHA-256，并在空白介质上完成一次刷写验证。

## 10. 版本边界

### 0.1.0 基础系统

显示、触摸、启动、首页、点击测试、Wi-Fi、系统信息、存储、电池只读状态、I²S 测试音、CH592F 基础 IAP。

### 0.2.0 设备完善

电池告警策略、充电历史、声音主题、离线升级包、显示 profile 管理和统一日志导出。

### 1.0.0 产品化

只在真实硬件连续运行、断电恢复、升级回滚和镜像重刷均通过后发布；不以页面数量作为 1.0 标准。
